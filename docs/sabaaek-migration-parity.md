## نموذج الهدف المرحلي

المرحلة الأولى المقترحة: نسخة واجهة staging على Cloudflare Static Assets، مع إبقاء Worker API الإنتاجي للقراءة فقط وعدم تغيير D1 أو Supabase.

المرحلة الثانية المقترحة: تقييم Better Auth مع D1 في Worker مستقل للتجربة فقط، مع اختبار الجلسات والأدوار وسجل التدقيق قبل التفكير في نقل الإدارة.

Turnstile طبقة مساعدة لتقليل الروبوتات، وليس بديلاً عن التحقق server-side. KV يستخدم للكاش غير الحساس فقط؛ مصدر الحقيقة للصلاحيات والأسعار المنظمة هو D1 أو نظام الإدارة الحالي الموثق.

## معايير عدم التبديل

لا يتم تبديل DNS أو رابط الإنتاج إذا فشل أي مما يلي: تطابق الواجهة والبيانات، عمل النطاقات الثلاثة، غياب الطلبات المكررة، عدم وجود overflow أو قص، نجاح القراءة على المقاسات المعتمدة، رفض الإدارة غير المصادق عليها، نجاح rollback، أو عدم وضوح مصدر البيانات والنسخ الاحتياطية.

## عناصر تحتاج قراراً أو وصولاً من المستخدم

توفر أسماء DigitalPlat القصيرة لا يمكن إثباته من بحث عام؛ يتطلب فحصاً داخل حساب DigitalPlat أو حجزاً يوافق عليه المستخدم. لا يتم طلب كلمة مرور أو رمز تحقق في المحادثة، ولا يتم حجز نطاق أو تغيير DNS دون موافقة صريحة منفصلة.
